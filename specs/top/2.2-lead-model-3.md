> Status: hot skeleton

## Purpose

- define the leadership and authority model that sits above execution details
- define which ownership boundaries belong to role semantics rather than to tooling accidents
- relate the future lead model to the currently active working role set

## Confirmed Oracle Points

- `Lead Model (3)` remains a top-level design document to be written first.
- The system must preserve clear role separation instead of mixed authority.
- `NOTA / Arch / Dev / Agent` currently remain the active working projection in the repo.
- `NOTA` is not `Arch`.
- Detailed strategy decomposition and issue splitting do not belong to `NOTA`'s top role.
- Authority separation should remain explicit instead of mixed permissions.

## Current Boundary Reading

- `NOTA` should remain the top secretary/control surface rather than collapsing into `Arch`
- `Arch` should continue to own strategy-level decomposition work
- mixed permission designs should be treated as boundary failures rather than convenience features
