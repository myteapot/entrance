# 1.1 OS Design (Core)

> Status: hot skeleton

## Purpose

- define the OS/core boundary of Entrance
- define which limits are enforced structurally rather than conversationally
- serve as the top mount point for capability, routing, and ownership constraints

## Confirmed Oracle Points

- Entrance keeps `OS + hierarchical state machine + compiler` as the foundational triple.
- Entrance must keep an OS/core design layer rather than collapse into a single harness abstraction.
- Hard capability boundaries should be enforced by runtime structure rather than prompt wording alone.
- Sandboxed execution and bounded worktrees are the default direction for lower execution roles.
- Lower execution roles must not directly mutate Arch-owned project state.
- NOTA must not directly mutate project-level Arch state or project-level issues.
- Permission separation should be enforced by hard routing, ownership, and capability boundaries.

## Current Boundary Reading

- lower execution roles should run inside bounded rooms or worktrees
- sandboxing is the default direction for lower execution roles
- authority separation should be treated as a single-writer problem rather than as a courtesy rule
- cross-role influence should pass through routing and ownership boundaries instead of direct mutation
