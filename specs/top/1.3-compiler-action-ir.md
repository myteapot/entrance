# 1.3 Compiler And Action Primitive Design

> Status: hot skeleton

## Purpose

- define the compiler-facing action layer of Entrance
- define how role boundaries become executable constraints rather than prose-only guidance
- define how routing, rooms, and action verbs fit under the top design

## Confirmed Oracle Points

- Entrance needs a compiler layer and an action-primitive layer.
- State-machine and compiler thinking should be used to constrain model behavior.
- Role boundaries must compile into harder internal actions instead of remaining soft narrative intent.
- Hard routing should compile role boundaries instead of leaving them as soft conventions.
- `NOTA` top surface remains the `do / learn / chat` triad.
- Logical dependency and execution dependency must be treated as different things.

## Current Boundary Reading

- the compiler layer should turn role semantics into enforceable transitions and packets
- `NOTA` top surface can stay compact while lower role actions become stricter
- hard routing belongs to compiled control semantics rather than to after-the-fact review
- this document should stay below the whole-system state machine and above concrete runtime implementation
