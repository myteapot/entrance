# 1.2 Hierarchical State Machine Design

> Status: hot skeleton

## Purpose

- define the whole-system state machine rather than a role-local fragment
- define how `NOTA / Arch / Dev / Agent` coexist inside one larger machine
- define how simulation, repair, upward handoff, and escalation interact

## Confirmed Oracle Points

- Entrance needs a top-level hierarchical state machine design.
- The whole-system state machine must be designed for the system together rather than only one role in isolation.
- The design target must cover semantics from `NOTA` through `Arch / Dev / Agent`.
- Simulation must gate upward handoff at every level.
- If local self-critique and local repair can solve the issue, the upper level should not be disturbed.
- Avoidable Human wake-up should be structurally reduced.
- High parallelism remains a target, but logical dependency and execution dependency must be treated separately.

## Current Boundary Reading

- this document owns the whole-system graph, not only one role's local cycle
- upward handoff is the primary place where simulation gate becomes structurally visible
- lower levels should not treat upper levels as smoke-test surfaces
- the machine should preserve room for high parallelism without flattening real dependency structure
