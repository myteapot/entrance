# Control

> Status: hot root

## Purpose

- hold the compressed hot-root summary for authority, control topology, and runtime admission
- separate semantic control law from subordinate execution lanes

## Confirmed Oracle Points

- Human is the final sovereign.
- `NOTA` is the Human-facing boundary host and the only normal semantic ingress/egress.
- `NOTA` is also the only global continuation authority in `v0` post-consolidation.
- `Policy` is the highest internal strategy slot, not a global mutable superuser.
- `Arch / Dev / Agent` are bounded lanes, not peer continuation authorities.
- `Human / NOTA / Policy / Arch / Dev / Agent` must obey one authority matrix rather than role-local folklore.
- Cross-slot semantic effect must travel through routed objects and runtime-owned delivery surfaces.
- Parallel worker windows are allowed only as subordinate execution under one `NOTA`-selected milestone, not as multiple peer schedulers.
- Continuation planning must advance one semantic boundary-step at a time and auto-skip already-landed cuts.
- Semantic cycle budget is distinct from execution retry budget.
- anti-Zeno is part of the control discipline now and must remain visible in runtime status surfaces.
- anti-Zeno budget exhaustion must force bounded closure, repair, or explicit human decision instead of infinite recursion.
- Long-term direction lands in `design decisions`, while the currently active operating cut lands in runtime `checkpoints` and `acceptance bundles`.
- The compressed hot-surface target remains `Machine / Control / Truth + Phase Todo + Pending + README`.

## v0 Control Split

- the persistent `NOTA` window refreshes shared truth, audits level claims, chooses the active milestone, and records checkpoint or decision changes
- worker windows own one bounded lane at a time and must return evidence, receipts, commits, or blockers back to `NOTA`
- multiple windows are an execution convenience, not multiple `NOTA`s
- no worker lane self-promotes the global phase, rewrites the top strategy, or creates a second continuation authority

## Enforcement Direction

- authority must be machine-readable in DB-backed runtime truth rather than only descriptive in docs
- `repair` is a first-class closure lane, not an informal comment field
- invariant failure should downgrade to repair or blocked status rather than silently mutating control truth
- projection refresh may follow truth writes, but it must never race ahead of truth writes
- host and worktree ownership remain subordinate runtime resources, not peer continuation roots
